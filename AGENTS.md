# Repository guidance

## Authoritative source

- Treat `src/` as the authoritative development source.
- Do not manually edit `pokeclicker-automation.user.js`; it is generated by `npm run build` and remains at the repository root for Tampermonkey update compatibility.
- `src/main.js` defines the exact assembly order. The modules intentionally share one IIFE lexical scope, so inspect earlier shared declarations before moving or renaming code.

## Making changes

- Inspect the relevant feature module and only the shared modules it directly depends on.
- Preserve current PokéClicker Helper behavior unless the user explicitly requests a behavior change.
- Preserve storage keys, stored value formats, defaults, startup timing, and global PokéClicker access.
- Avoid unrelated refactoring, framework additions, and speculative dependency changes.
- Keep module boundaries meaningful. Do not split code into tiny files without a maintenance benefit.
- Update `README.md`, this file, and the source manifest when the project structure changes.

## Validation

- Run `npm run build` after every source change.
- Run `npm run check` before reporting completion.
- Review the generated userscript diff as well as the source diff.
- Do not claim live browser or in-game validation unless it was actually performed.

## Repository actions

- Do not commit or push unless the user explicitly requests it.
